# Спецификация Протокола Feline P2P Art Cloud (CatP2P v1.0)
## Открытый стандарт децентрализованной социальной сети любителей кошек и живописи

---

## 1. Концепция и архитектурная парадигма

**Feline P2P Art Cloud** — децентрализованная одноранговая (P2P) социальная сеть, в которой пользователи превращают своих домашних кошек в героев картин в различных мировых стилях живописи с помощью ИИ, а хранение и распространение контента осуществляется децентрализованно силами самих пользовательских устройств.

### Ключевые постулаты архитектуры:
1. **Edge-Hosted Quota (Фиксированная квота 8 ГБ)**:
   Каждая полноправная нода резервирует ровно 8 000 МБ дискового пространства.
2. **Нулевой серверный оверхед (Zero Server Bill)**:
   У сети нет централизованного облачного S3/CDN хранилища для медиафайлов. Все полотна хранятся на устройствах владельцев.
3. **5-кратная репликация целых файлов (Whole-File 5-Replica Model)**:
   Каждая картина хранится в 5 полных копиях:
   - 1 копия — у автора (оригинальная нода-создатель);
   - 4 копии — у 4 взаимных пиров («Круг поручителей» / Mutual Custodians).
4. **Отказ от шифрования контента (Zero-CPU Storage)**:
   Изображения в социальной сети публичны по своей природе. Отказ от симметричного шифрования (AES/ChaCha20) и фрагментации на мелкие чанки исключает нагрузку на процессор и аккумулятор мобильных устройств. Файлы отдаются напрямую из локальной файловой системы (Stream-on-demand).
5. **Криптографическая верификация авторства (Ed25519 / ECDSA P-256)**:
   Каждая картина и метаданные подписываются приватным ключом автора. Подмена авторства или модификация пикселей невозможна, так как контент адресуется по SHA-256 хешу (Content-Addressed Storage).
6. **Правило чистоты контента (Cat Sanctity Rule)**:
   Сеть предназначена исключительно для кошачьего искусства. Нарушение тематики ведет к автоматическому отказу в репликации и снижению репутации ноды.

## 2. Модель распределения квоты 8 ГБ (Mutual Storage Contract)

Каждая нода распределяет свои 8 000 МБ следующим образом:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        НОДА: 8 000 МБ (8 ГБ)                           │
├──────────────────────┬─────────────────────────────────────────────────┤
│   Собственные работы │            Квота взаимных партнеров             │
│       (1 600 МБ)     │                    (6 400 МБ)                   │
│                      ├─────────────┬─────────────┬─────────────┬───────┤
│                      │   Пир №1    │   Пир №2    │   Пир №3    │Пир №4 │
│                      │  (1 600 МБ) │  (1 600 МБ) │  (1 600 МБ) │(1600М)│
└──────────────────────┴─────────────┴─────────────┴─────────────┴───────┘
```

- **Собственные картины**: 1 600 МБ (при среднем весе шедевра в 2 МБ это ~800 картин высокого разрешения).
- **Взаимный резерв**: 6 400 МБ, разделенный поровну между 4 пирами-партнерами (по 1 600 МБ на каждого).
- **Правило взаимности (Tit-for-Tat Storage)**:
  Нода $A$ хранит картины Ноды $B$ до тех пор, пока Нода $B$ хранит картины Ноды $A$. Если пир выходит из строя или удаляет файлы партнера, контракт расторгается, и нода находит нового поручителя из пула доступных пиров.

## 3. Спецификация пакетов и протоколов межсетевого обмена

### 3.1. Идентификатор ноды и автора (CatID)
Идентификатор ноды формируется на основе открытого ключа (Ed25519 или ECDSA P-256):
```
NodeID = "catnode_" + Base58(SHA256(PublicKey))
```

### 3.2. Рукопожатие и контракт взаимного хранения (Handshake & Storage Agreement)

#### Запрос на заключение соглашения (`STORAGE_CONTRACT_REQ`):
```json
{
  "type": "CATP2P_STORAGE_CONTRACT_REQ",
  "version": "1.0",
  "senderNodeId": "catnode_8FjXk...qZ",
  "allocatedQuotaBytes": 1677721600, // 1600 MB
  "currentUsageBytes": 345000000,
  "timestamp": 1789835000000,
  "publicKey": "-----BEGIN PUBLIC KEY-----\n...",
  "signature": "Hex(Sign(senderNodeId + allocatedQuotaBytes + timestamp))"
}
```

#### Ответ с подтверждением контракта (`STORAGE_CONTRACT_ACK`):
```json
{
  "type": "CATP2P_STORAGE_CONTRACT_ACK",
  "version": "1.0",
  "contractId": "contract_a1b2c3d4e5",
  "status": "ACCEPTED", // ACCEPTED | QUOTA_FULL | REJECTED
  "allocatedQuotaBytes": 1677721600,
  "responderNodeId": "catnode_3PmKz...wX",
  "timestamp": 1789835005000,
  "signature": "Hex(Sign(contractId + status + responderNodeId))"
}
```

### 3.4. Транспортный протокол передачи файлов
- **Синхронизация между пирами**: WebRTC DataChannel (браузеры) / QUIC Streams (нативные ноды).
- **Запрос картины по SHA-256**:
  ```
  GET_CAT_ARTWORK(sha256) -> Binary Stream -> Write directly to disk
  ```
- **Проверка при получении**:
  Получатель читает бинарный поток, вычисляет `SHA256(payload)`. Если хеш совпадает с `artworkId`, файл сохраняется в директорию соответствующего пира. Шифрование и дешифровка не производятся.

## 4. Контроль чистоты контента (Cat Sanctity Consensus)

Сеть отвергает контент, не относящийся к кошкам:
1. **L1: Локальный инференс MobileNet / YOLO-Cat**:
   Перед отправкой файла нода-автор запускает сверхлегкую классификацию (порог уверенности `cat > 0.85`).
2. **L2: Социальный консенсус (Dispute)**:
   Если пир получает манифест без изображения кота, он отправляет сообщение `CAT_VIOLATION_REPORT`. При накоплении 3 подтверждений от разных нод контент помечается как `CONDEMNED` и исключается из автоматической репликации.
