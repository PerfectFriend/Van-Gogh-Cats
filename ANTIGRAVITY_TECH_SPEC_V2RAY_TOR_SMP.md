# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) И АРХИТЕКТУРА ДЛЯ ANTIGRAVITY
## Интеграция V2Ray, Tor, SMP и XFTP в P2P-сеть Van Gogh CryptoCats

---

## 1. НАЗНАЧЕНИЕ И ЦЕЛИ
Данный документ определяет архитектуру расширения транспортного и сетевого стека децентрализованной галереи **Van Gogh CryptoCats** для реализации на физических хостах и в среде Antigravity.

Цель — обеспечение **100% устойчивости к сетевой цензуре, DPI-фильтрации и блокировкам провайдеров**, а также масштабирование P2P-обмена картинами и сообщениями через специализированные протоколы **SMP** и **XFTP**.

---

## 2. АНТИЦЕНЗУРНЫЙ МОСТ: V2RAY & TOR (TRANSPORT LAYER)

### 2.1. V2Ray / Xray Bridge
* **Протоколы обфускации**: VLESS + XTLS / Reality, WebSocket + TLS (CDN fronting), gRPC.
* **Назначение**:
  * Обход глубокого анализа пакетов (DPI) и сетевых фильтров при сигналинге WebRTC и синхронизации узлов.
  * Создание защищённого туннеля между двумя хостами Ubuntu и мобильными клиентами даже в изолированных сетях.
* **Конфигурация демона**:
  * Размещение в `/etc/vangogh/v2ray/config.json`.
  * Локальный SOCKS5/HTTP inbound: `127.0.0.1:10808` / `127.0.0.1:10809`.
  * Автоматический fallback: если прямой WebRTC ICE заблокирован → переключение трафика через V2Ray мост.

### 2.2. Tor Hidden Services (.onion v3)
* **Назначение**:
  * Полная анонимизация и доступность хоста без белого статического IP-адреса и без необходимости проброса портов (NAT traversal).
  * Резервный канал обнаружения P2P-пиров (Tor Rendezvous Point).
* **Спецификация**:
  * Служба Tor Hidden Service v3 для HTTP/WebSocket сигналинга: порт `3000` проксируется на виртуальный `.onion` адрес.
  * Хранение onion-ключа в защищённом каталоге ноды: `/var/lib/tor/vangogh_onion/`.
  * Публикация `.onion` адреса в Web of Trust профиле автора (рядом с BIP-39 отпечатком).

## 3. ПРОТОКОЛЫ SMP И XFTP ДЛЯ ЧАТОВ И ФАЙЛОВ

### 3.1. Протокол SMP (Simple Messaging Protocol)
* **Назначение**:
  * Асинхронные приватные чаты между художниками, групповые гильдейские чаты и публичные каналы выставок.
* **Принцип работы**:
  * Одноранговые однонаправленные криптографические очереди сообщений без единого идентификатора пользователя на сервере.
  * Двойной храповик (Double Ratchet / Signal Protocol) поверх SMP для Perfect Forward Secrecy (PFS).
  * Поддержка широковещательных каналов галереи (Publish/Subscribe) с цифровой подписью автора полотен.

### 3.2. Протокол XFTP (Extensible File Transfer Protocol)
* **Назначение**:
  * Передача высококачественных несжатых полотен 1024×1024, архивов `.catpack` и шардов Swarm-хранилища.
* **Принцип работы**:
  * Разделение файла на чанки с контрольными суммами BLAKE3 / SHA-256.
  * Параллельная скачка из нескольких пиров (Multi-source swarming) через Tor/V2Ray туннели.
  * Докачка при обрыве соединения и автоматическая проверка дерева Меркла.

## 5. ПОШАГОВЫЙ ПЛАН РЕАЛИЗАЦИИ В ANTIGRAVITY

1. **Этап A: Развёртывание V2Ray/Tor демонов на Ubuntu стенде**:
   * Настройка `tor` сервиса с генерацией v3 Hidden Service.
   * Настройка клиента `xray-core` с поддержкой Reality и WebSocket fallback.
2. **Этап B: Интеграция SMP сервера и клиентского шлюза**:
   * Развёртывание легковесного SMP-сервера очереди на первом Ubuntu хосте.
   * Создание моста между браузерным P2PNetworkHub и SMP через локальный WebSocket (`ws://127.0.0.1:5222`).
3. **Этап C: Интеграция XFTP для передачи пакетов Swarm**:
   * Расширение `p2pSwarmChunker.ts` для взаимодействия с XFTP daemon.
   * Тестирование отказоустойчивой передачи полотен при искусственном разрыве связи.
4. **Этап D: Тестирование в боевых условиях (Dual-Host LAN & WAN)**:
   * Проверка прохождения трафика через DPI-симуляторы и строгие сетевые фильтры.
