## 4. Что осталось и что найдено нового

### 4.1. Подмена отправителя в чате (высокий)

**Где:** `p2pChatProtocol.ts`, строка 187 — при расшифровке берётся `envelope.senderEcdhPublicKeyJwk || getPeerEcdhPublicKey(senderPeerId)`, то есть ключ из самого конверта приоритетнее закреплённого.

**Чем опасно:** атакующий пишет `senderPeerId: "Тео"`, подставляет **свой** ключ ECDH — конверт честно расшифруется, а в UI сообщение придёт «от Тео». AAD этого не ловит, потому что строка `senderPeerId` тоже под контролем атакующего.

Тот же корень: `registerPeerEcdhPublicKey` молча перезаписывает ключ пира, а ключи приходят через сигнальный сервер, поэтому сервер или тот, кто его контролирует, может подменить ключ; защитой остаётся только ручная сверка safety number. Старые конверты v1 расшифровываются по публичным peerId, значит любой может подделать v1-сообщение, если принимать их из сети.

**Решение:** сначала искать закреплённый ключ; если закреплённого нет — принимать ключ из конверта один раз (TOFU) и показать предупреждение; если закреплённый отличается — отклонить и показать «ключ собеседника изменился». v1 принимать только из локального хранилища, не из сети.

### 4.2. Production-сервер не запустится без devDependencies (высокий, по коду)

`server.ts` импортирует `vite` на верхнем уровне, а в `dist/server.cjs` это превращается в `require("vite")` (строка 38 бандла); сам `vite` лежит в `devDependencies`. После `npm ci --omit=dev` (типичный Docker-образ) процесс упадёт на старте. Я проверил наличие `require` в бандле, но образ без devDependencies не собирал.

**Решение:** в production-ветке не импортировать `vite`: динамический `await import('vite')` только при `NODE_ENV !== 'production'`.

### 4.3. Регистрация пиров открыта, очереди сигналов утекают (средний, подтверждено)

- `/api/p2p/register` не требует входа. Любой может занять свободный `peerId` (например, когда у жертвы истёк TTL 35 с), а 200 фейковых пиров заполняют комнату (`SIGNALING_ROOM_FULL`).
- `signal/send` принимает адресата, которого не существует: я отправил три сигнала на `ghost_1..3`, все получили `success: true`. Очереди для таких адресатов нигде не удаляются (после фильтрации по TTL остаются пустые массивы) — это медленная утечка памяти.
- Публичный `/api/health` показывает `modelStatus.missingModels` и текст ошибки — для production лучше оставить только `status`.

**Решение:** требовать Firebase-токен при регистрации и держать не больше одного пира на `uid`; отвечать 404 на неизвестного адресата; удалять пустые очереди; задать `maxPayload` для WebSocket.

### 4.4. Ложные срабатывания проверки «только коты» (средний, подтверждено запуском)

Регулярное выражение `кот\p{L}*` ловит любые слова на «кот»: «**Который** читает письмо», «**Котлета** на тарелке», «**Котёл** с супом» проходят как коты. Слово «который» встречается в большинстве русских описаний, так что проверка по тексту почти ничего не отсекает. Плюс «Cat with a dog on a couch» теперь проходит (это политика продукта, но убедитесь, что вы этого хотите).

Визуальная проверка на сервере срабатывает «мягко»: при ошибке или неизвестной модели возвращает `true` (fail open), а модель `gemini-4-hydrogen` не подтверждена. На `edit-image` проверки кота нет.

**Решение:** точный список форм слова (выражение и тесты в послании ниже), в vision-проверке при ошибке логировать и считать счётчик, на правках картинок решить продуктово.

### 4.5. Ключи в IndexedDB и forward secrecy (средний)

Приватные ключи ECDH и ECDSA хранятся как **extractable** JWK; XSS заберёт их целиком. IndexedDB умеет хранить объекты `CryptoKey` — делайте ключи неизвлекаемыми. Схема «статический ECDH на статический ECDH» не даёт forward secrecy: компрометация долгого ключа раскрывает всю старую переписку. Для беты допустимо, на будущее — эфемерный ключ на сообщение или double ratchet. Защиты от повторной отправки конверта (replay) по envelopeId я не нашёл.

### 4.6. Мелочи

- **TURN:** по-прежнему только STUN Google (`stun:stun*.l.google.com`), за симметричным NAT и мобильными сетями соединение не поднимется.
- **Модели Gemini:** `gemini-nano-banana-2.1`, `gemini-3.1-flash-lite-image`, `gemini-3-pro-image`, `gemini-3.8-flash-lite-tts`, `gemini-4-hydrogen` — зонд при старте уже есть, но без ключа я его не мог проверить. Прогоните с реальным ключом и посмотрите `/api/health`.
- **Жёсткий `projectId`** `gen-lang-client-…` в `server.ts` как запасной вариант — лучше падать с понятной ошибкой.
- **Своя проверка JWT** (RS256 и сертификаты Google) написана аккуратно, но не умеет проверять отзыв токена; можно заменить на `firebase-admin` или `jose`.
- **`npm audit`:** те же 4 high через `firebase → @grpc/grpc-js`, `npm audit fix --force` по-прежнему не применять (откат на `firebase@9.14.0`).
- **Картинки:** `src/assets` — 27 МБ JPEG; в precache они больше не входят, но каждому новому посетителю качать всё равно много. `sharp` у вас уже есть: перекодируйте в WebP/AVIF.
- **Менеджер пакетов:** в архиве только `bun.lock`, а скрипты рассчитаны на npm — выберите один.
- **Лимитеры** `express-rate-limit` и состояние сигналинга живут в памяти процесса — при нескольких инстансах Cloud Run лимиты и комната пиров разъезжаются (нужен Redis/общий стор или один инстанс).

## 1. Закрепи ключи собеседника (P0, \~час)

Сейчас в `decryptChatPayload` ключ из самого конверта приоритетнее закреплённого. Поменяй порядок и добавь защиту от смены ключа:

```ts
const pinned = getPeerEcdhPublicKey(envelope.senderPeerId);
const claimed = envelope.senderEcdhPublicKeyJwk;

let remoteJwk: JsonWebKey | null = null;
if (isRecipient) {
  if (pinned && claimed && canonicalizeEcPublicJwk(pinned) !== canonicalizeEcPublicJwk(claimed)) {
    throw new Error('PEER_KEY_CHANGED: ключ собеседника изменился, сообщение отклонено.');
  }
  remoteJwk = pinned || claimed || null;       // без pinned — TOFU, покажи предупреждение в UI
} else {
  remoteJwk = getPeerEcdhPublicKey(envelope.recipientPeerId);
}
```

И в `registerPeerEcdhPublicKey` не перезаписывай существующий ключ молча: если пришёл другой — верни `false` и выставь флаг «ключ сменился» для интерфейса (рядом покажи safety number и кнопку «Подтвердить новый ключ»). Конверты `v1` принимай только из локального хранилища, а не из сети: их ключ выводится из публичных peerId, значит подделать их может любой.

## 3. Сигналинг: регистрация, очереди, лимиты (P0/P1)

Четыре небольшие правки в `server.ts`:

```ts
// 2) в /signal/send — не принимай сигналы для неизвестных адресатов

for (const [targetId, queue] of queuedSignals.entries()) {
```

## 4. Проверка «только коты» (P0, 20 минут)

Регулярка `кот\p{L}*` пропускает «который», «котлета», «котёл». Замени на явные формы слова. Я проверил это выражение: все 10 «котовых» фраз проходят, все 10 «не-котовых» отсекаются.


Добавь в `catSanctity.test.ts` оба набора: «Кот на подсолнухах», «Котёнок спит», «Мурлыка у окна» → true; «Который читает письмо», «Котлета на тарелке», «Мурал на стене», «Кошмар в Арле», «catalog of paintings» → false. ## 5. Ключи в IndexedDB (P1)

Если `getCryptoKeyPair` умеет хранить объекты, сохраняй сами `CryptoKey`, а не JWK, и генерируй приватные ключи неизвлекаемыми:

```ts
const keyPair = await crypto.subtle.generateKey(
  { name: 'ECDH', namedCurve: 'P-256' },
  false,                 // extractable: false — приватный ключ не вытащить через exportKey
  ['deriveBits']
);
// publicKey экспортируй отдельно: exportKey('jwk', keyPair.publicKey) работает и для неизвлекаемой пары
```

Будь готов к одному компромиссу: резервная копия ключа станет невозможной. Тогда восстановление — через seed-фразу (детерминированно получай ключи из неё) или через новый ключ с повторной сверкой safety number.

На будущее: у схемы «статический ECDH на статический ECDH» нет forward secrecy. Следующий шаг — эфемерный ключ на каждое сообщение (отправитель кладёт одноразовую публичную пару в конверт) или double ratchet. Добавь также защиту от повторной отправки конверта: храни последние `envelopeId` и отклоняй дубликаты.

## 8. Картинки и CI (P1)

Картинки в `src/assets` весят 27 МБ. Ты уже вынес их из precache — теперь сожми сами файлы. `sharp` у тебя в зависимостях:

```ts
// scripts/optimize-images.mjs
import sharp from 'sharp';
import { readdir } from 'node:fs/promises';
for (const f of await readdir('src/assets/images')) {
  if (!/\.jpe?g$/i.test(f)) continue;
  const base = f.replace(/\.[^.]+$/, '');
  for (const w of [480, 960, 1600]) {
    await sharp(`src/assets/images/${f}`).resize({ width: w, withoutEnlargement: true })
      .webp({ quality: 78 }).toFile(`src/assets/images/${base}-${w}.webp`);
  }
}
```

Подключай через `srcset` и `loading="lazy"`. Затем добавь CI (GitHub Actions): `tsc --noEmit`, `npm test`, `vite build`, `npm audit --omit=dev`, плюс тесты `firestore.rules` на эмуляторе (`@firebase/rules-unit-testing`), для них у тебя уже есть список атак в `security_spec.md`. Включи App Check и ограничь web-ключ Firebase по доменам.

## 9. Идеи по функционалу

1. **Реальная сетевая загрузка роя (Swarm).** Сейчас пиры и скорости придуманы (README это честно признаёт). Собери её поверх передачи полотен, которая у тебя уже работает: разные части файла качай у разных пиров, каждую проверяй по корню Меркла.
2. **Верификация собеседника.** Рядом с safety number добавь QR-код для сверки лицом к лицу и значок «ключ подтверждён» в списке чатов.
3. **Подписанные вердикты суда.** Вердикт подписывает ECDSA-ключ каждого аудитора, а бан — решение не локального флага, а набора подписей; тогда его нельзя обойти очисткой хранилища.
4. **Приватные галереи друзей.** Доступ по подписанному приглашению, а не по общему списку пиров.
5. **Остаток квоты в студии.** Показывай пользователю, сколько генераций у него осталось, прежде чем он нажмёт кнопку (лимиты у тебя уже есть: 10 за 15 минут).
6. **История версий в редакторе:** откат правок и сравнение «до/после».
7. **Доступность:** фокус-ловушки в модалках, `aria-live` для уведомлений, `prefers-reduced-motion` для психоделического фона, проверка арабской раскладки справа налево.
8. **Телеметрия ошибок P2P** (Sentry или аналог): сейчас отказ ICE или DataChannel виден только в консоли пользователя.
9. **Pro:** либо настоящая оплата (Stripe + custom claim в Firebase Auth, проверка в `verifyIdToken`), либо оставь честным «локальным переключателем» и убери слово Pro из витрины.
